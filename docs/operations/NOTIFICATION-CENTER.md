# In-app notification center

Open **Notification center** from the administration workspace. Custom messages can target a course, programme or one or more plans. Additional selections narrow the audience; a single matching active subscription must satisfy the complete selection. A durable delivery job selects recipients in bounded batches, deduplicated by student ID, and excludes expired, scheduled, manually locked or unavailable academic mappings. Eligibility is rechecked as each batch is delivered. Subscriptions created after delivery completes do not receive historical messages automatically.

The composer has four editable templates, an audience estimate, attachments and final send confirmation. The server rechecks eligibility when sending. Retries of the same request ID return the original notification rather than delivering twice.

Regular notifications are generated transactionally for new material versions, copied published materials and newly published session revisions. This includes deferred PDF publication by the worker. Existing publications can be recovered through **Sync published updates**, after the administrator confirms delivery to current eligible students. Recovery preserves original publication dates, is idempotent, and excludes unpublished drafts. The student inbox follows shared change checks; the admin list refreshes every 15 seconds and on window focus. Repeating publication of an unchanged published version does not deliver again. Hidden material copies do not send notifications. Material notifications open the protected preview; they do not grant access to the original PDF.

Students use **Notifications** in their workspace. Listing messages does not mark them read. Opening a message records its first read time; the viewer count is the number of distinct recipients who opened it. Administrators can inspect viewer names and timestamps. These are message-open receipts, not proof of reading or downloading every attachment. Super admins can see all messages; content managers see their own messages and viewer lists.

Attachments support PDF, PNG, JPEG, TXT, CSV, DOCX and XLSX: up to three files, 5 MB each and 10 MB total. File bytes are stored in PostgreSQL separately from list metadata. Downloads require authenticated recipient or sender access and are served as attachments with no-store and nosniff headers. Expired or manually locked students retain profile access but cannot open the inbox or download files until access is restored.

Apply all migrations and start `notification-worker` with the API and PDF worker. Monitor delivery progress, retries and queue age as described in [DevOps handoff](DEVOPS-HANDOFF.md#capacity-migrations-and-notification-worker).
